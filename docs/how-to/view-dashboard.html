What Elefante Home is for

Applies to the current Elefante Home source prototype, built and rendered against the current local snapshot on 2026-09-02.

Release boundary this guide documents the six-workspace source prototype. Installing a local candidate does not publish a release. The installed package receipt identifies the exact build; source checks alone do not prove which dashboard is running.

Elefante Home is the advanced local control room for three jobs:

  1. Global understanding. Memory Intelligence and Connections inspect everything represented in the current snapshot; no project is required.
  2. Task intelligence. Remember, Recall, and Correct improve the governed memory bundle Elefante can supply to one task; project identity is required at this boundary.
  3. Continuity. Recover checks health, protects data, restores safely, and produces bounded support evidence.

Home is not an IDE feature. Host, port, launch origin, browser, and agent are transport details—not separate Elefante products or alternate Home experiences.

Open Home

For an installed customer runtime, open this address in any local browser:

http://localhost:8000

This is an entry address, not a product mode. A development or packaged build may use a different loopback address; the purpose, workspaces, evidence contract, and user workflow must remain identical.

The installed Elefante daemon owns the loopback-only page. A bare visit requests its own short-lived local management session. If exactly one active project is available, Home binds it automatically. If several are active, Home asks which one should own this session's managed actions.

elefante-DashboardOpen remains an optional agent convenience; it is not the customer entry requirement. Its refresh=true option regenerates the dashboard snapshot before opening Home. The header's Reload snapshot button and a normal browser reload only reread the snapshot that already exists.

The operating model: snapshot plus bounded control

Home combines two layers without mixing their authority.

1. The inspection snapshot

The dashboard server reads one generated file, dashboard_snapshot.json. It does not open SQLite vectors or Kuzu in response to browser inspection. The snapshot provides memory records, entities, relationships, counts, health signals, usage summaries, and Project Registry projection data.

Snapshot search is lexical. It is not the same query path as MCP Recall, and it does not expose Recall's vector, concept, co-activation, authority, or temporal signal breakdown.

2. The local management session

A direct local visit can request a short-lived, origin-bound capability from the loopback daemon. The raw capability stays in browser memory. A legacy capability-bearing URL fragment, when supplied by an agent, is removed from browser history before the page renders.

The capability permits only named Project, Remember, Recall-test, Correct, Resolve, and Recover routes. It is not a generic store, file, shell, MCP, or query proxy. Mutations retain their preview, explicit confirmation, one-use ticket, exact-state checks, postconditions, and rollback gates.

If the session expires during Recover, its error remains visible with Reconnect Home. That button requests a new local session; it never retries a backup, restore, or report automatically. Inspect a new plan and confirm it before trying the operation again.

If operational control is unavailable, the snapshot can remain inspectable while Home says exactly what is missing: No operational receipt in this environment. That is an evidence boundary, not a claim that Elefante itself failed.

Main navigation

Home has six top-level workspaces:

  1. Home — one product purpose, current evidence, three operator jobs, and one recommended next action.
  2. Recall — one ephemeral project-scoped Recall Check and its bounded evidence receipt.
  3. Memory Intelligence — complete snapshot library, review signals, detail, correction, and conflict resolution.
  4. Connections — topics, stored vitality, explicit relationships, and grounded Decision Graph trails.
  5. Projects — scope registry, legacy assignment, and strict isolation.
  6. Recover — health, backup, restore, support report, and package handoff.

The number keys 1 through 6 switch to those workspaces when focus is not inside an editable control or dialog. Escape closes the open memory detail and clears snapshot search, including when search has focus. The detail panel stays inside the memory workspace and does not cover top navigation. Dialogs also support Escape; Remember and correction dialogs cannot be dismissed or changed while a managed operation is running.

Starting a new snapshot search closes the previous memory detail, so an empty search does not leave an old record looking like a new result.

Footer

  • live local session — named management routes are available;
  • connecting local service — the page is establishing its loopback session;
  • local snapshot — inspection is available, but management is not active.

Home begins with the product promise: Make memory useful for the next task. It does not begin with a green light, a setup alarm, or a random memory. The opening panel explains that Elefante selects governed decisions, constraints, preferences, facts, and lessons while the dashboard lets advanced users understand, improve, and protect that system.

A project is an isolation boundary, not the entrance fee to understand Elefante. With no project, the user can inspect the complete snapshot. Before Recall or a write, Elefante must bind the exact project so unrelated work cannot enter the result. Choosing a project declares scope; it does not scan or ingest the project's files.

Remember

Remember appears on Home only when a live strict project context is ready. It preserves one durable decision, constraint, preference, or lesson—never passwords, keys, tokens, hidden reasoning, or full transcripts. The form accepts up to 8,000 characters plus a likely future Recall question of up to 1,000 characters. Elefante searches before writing, applies once, and checks the future question through governed Recall.

If overlap is found, Update existing and Supersede existing open the existing memory for review; they do not silently write. Keep both uses the explicit keep-both plan. Cancel changes nothing. Success requires a VERIFIED_COMPLETE receipt and the named postconditions.

Recall

Recall opens the dedicated Recall Inspector. Home does not run a hidden query, invent a question, or claim a selection occurred. See the complete evidence contract in Recall.

Correct

Correct opens Memory Intelligence. The action menu depends on the selected memory's represented lifecycle state:

ActionMeaning
EditFix a mistake without changing the intended meaning
ReplaceRecord a newer version while preserving the old history
ArchiveKeep the record inspectable but remove it from Recall delivery
RestoreReturn a manually archived, non-superseded record to Recall eligibility
Delete permanentlyRemove the memory and unshared attachments only after a temporary verified safety backup

A manually archived, non-superseded record offers Restore and Delete permanently. Other represented inactive records, including superseded records, offer only Delete permanently. The no-write plan remains authoritative and can still block the operation when its safety conditions are not met.

The managed flow is always: choose an action; explain why; provide a likely future Recall question; inspect a no-write plan; confirm its single-use ticket; apply once; verify store, graph, Home, and scoped Recall; then inspect the privacy-safe receipt. Protected memories add explicit acknowledgement. Permanent deletion adds exact DELETE confirmation. Its temporary safety backup is destroyed only after all postconditions pass. Older backups are not deleted and may still contain the memory; restoring one can bring that record back.

Resolve

Verified Resolve appears only for a represented conflict pair. The user chooses the authoritative winner, reviews the plan, and confirms one single-use ticket. Elefante then verifies that governed Recall supplies the chosen winner. Ambiguity does not choose a winner automatically.

Managed-action receipt states

Terminal stateMeaning
VERIFIED_COMPLETEThe change and all required postconditions passed
FAILED_NO_CHANGEThe requested operation did not complete and no state change was verified
FAILED_ROLLED_BACKThe operation failed, then the prior state was restored and verified

A receipt can show action, changed state, recoverability, rollback, operation ID, bounded error codes, and individual verification checks. Invocation alone is never presented as completion.

Recover

Recover opens the product-wide lifecycle surface described in Recover. Its controls become readiness evidence only after a timestamped check or verified operation receipt.

Recall: test governed selection

Recall is the truthful place to test what Elefante would supply for one real question. The first version is deliberately narrow: one ephemeral question, one active registered project, and one read-only check. It does not answer the question, write a memory, or create Recall history for dashboard convenience.

Memory scope names the memories available to this check, not the subject you must ask about. A preselected boundary needs no repeated setup. Overall browsing remains available in the Library without a project.

Run Recall Check returns bounded proof, not private memory content:

Status Meaning
supplied Governed Recall selected one or more project memories; Home shows selected count plus bounded IDs and titles
no_match No memories passed the matching rules. A relevant memory may still exist; this is not proof that abstention was correct. Use Inspect available memories to check the library.
blocked Conflict or governance stopped delivery
unavailable The Recall path could not be verified

The receipt may also show conflict count, active project, and verification time. A selected ID can open that record in Memory Intelligence. The selected memory content remains in the agent delivery path and is not copied into Home.

Opening a selected record or Inspect available memories clears an old snapshot search and opens Library, so previous filters cannot hide the record you asked to inspect.

The current question and receipt stay available when you inspect a record and return. They live only in this page's memory, not saved history. Changing the question or loading a newer snapshot clears the receipt; changing project or reloading the page clears both.

If the local session expires or reaches its request limit, use Reconnect Home. The reconnect control stays above open dialogs without covering the header or navigation, and your current question or correction draft remains available. Elefante does not rerun a check or repeat a change automatically. For a change, inspect a fresh plan and confirm it yourself.

The current contract does not expose per-signal reasons, withheld IDs, historical trace, answer quality, or task-outcome evidence. A supplied bundle does not prove that an answer was correct; no_match proves only that nothing was selected.

If no active project or local management session is available, Recall fails closed and points to Projects or Home. It never converts the all-memory view into a global Recall scope.

Session Intelligence

Session Intelligence remains on Home under the collapsed Advanced disclosure. It is a view-only surface and is off by default. The dashboard cannot grant consent or ingest usage. Without explicit local consent and a derived metadata-only snapshot, Home shows only the disabled explanation.

When evidence exists, the Signal Card can show event count, provider-actual input/output tokens, verified cost when known, accepted-outcome evidence, training hypotheses, and explicit unknowns. Provider-actual and estimated usage remain separate. Prompts, transcripts, responses, employee ranking, and sensitive-trait inference are outside this surface.

Memory Intelligence: inspect and review

Memory Intelligence presents every memory node returned from the current snapshot. The default graph response is bounded to 1,000 total nodes, so “overall” means the complete browser snapshot response, not an unbounded live-store query.

Library shows the complete snapshot corpus. Review narrows that same data to records carrying a direct non-healthy health signal or represented archive, deprecation, contradiction, redundancy, or supersession state. Review does not grade truth, usefulness, project scope, or whether correction is necessary.

The two search boxes are different

Vitality is not Recall relevance

The UI column is labelled Vitality, but its underlying snapshot score is the dashboard display score:

dashboard score = 50% temporal vitality
                + 25% memory-type weight
                + 25% engagement

The labels are:

Score Label
80-100 Fresh
60-79 Healthy
40-59 Aging
20-39 Fading
0-19 Dormant

Do not compare this number with a query's Recall score. Recall relevance is computed for one question through a different governed path.

Normal MCP retrieval is currently read-only and does not update access history. Consequently, Never means the snapshot records zero uses; it is not proof that the memory has never been useful or delivered through every possible path.

Health labels

Health is also separate from score:

Health Rule used at snapshot generation
At risk The memory is contradictory or superseded
Stale Otherwise, it has not been accessed for more than 90 days
Orphan Otherwise, it has no represented graph connection
Healthy None of the higher-priority conditions applies

Health is an inspection signal, not an automatic archive, merge, delete, or repair instruction.

Complete memory drawer

The drawer reveals only sections supported by the selected snapshot record:

  • title, type, ring, knowledge type, relative age, and health;
  • Summary and Content;
  • Metadata: topic, type, ring, knowledge, dashboard score, lifecycle, health, connections, processing, namespace, and source;
  • Provenance & scope: storage, source detail, project, workspace, scope, author;
  • Governance: authority, reliability, source verification, version, retention, injection policy, and user lock;
  • Correct controls allowed by lifecycle state;
  • concepts, saved Recall questions, surfacing rules, and tags;
  • active conflicts and the latest ten resolution events;
  • latest ten verified correction events;
  • up to eight related memories represented by snapshot edges;
  • Debug Info: ID, timestamps, archive/deprecation state, and supersession IDs.

A dash means the snapshot does not supply that field. Home does not infer a missing value.

Retrieval Explanation

Retrieval Explanation appears only when the record was opened from Snapshot search. It reports:

  • lexical match percentage for the typed query;
  • rank among the returned snapshot results;
  • configured storage backend recorded in the snapshot, such as SQLite; Not reported if absent—not the content's source, such as user input;
  • health label and reason;
  • explicit inbound/outbound relationships represented in the snapshot.

It explicitly does not claim to explain MCP Recall's vector, concept, co-activation, authority, or temporal signals because the dashboard API does not receive those per-query values.

Connections: understand relationships across memories

Connections is snapshot-wide and has three subviews.

Topics

Topics groups memories by snapshot topic, largest groups first. Each card shows:

  • topic name and memory count;
  • average stored vitality value;
  • counts by memory type;
  • up to four highest-vitality memory titles;
  • how many additional records remain in that topic.

The color palette separates categories visually. Color is not another score.

Vitality

Vitality computes a display-only breakdown of the current memory nodes:

  • average, highest, and lowest dashboard score;
  • count at each exact score;
  • memory-type distribution;
  • topic distribution;
  • six highest-scored records.

These are snapshot composition metrics, not Recall quality or task-outcome measurements. The score bars use display thresholds at 80 and 60 on the snapshot's 0-100 dashboard-score scale. They are visual grouping bands, not truth, utility, or Recall-quality grades.

Decision Graph

The Decision Graph builds trails only from explicit memory-to-memory causal, correction, contradiction, dependency, enablement, governance, and safeguard relationships. Semantic similarity edges do not form reasoning trails.

The header can report:

  • grounded trail count;
  • old assumptions, derived from deprecated or superseded records;
  • explicit safeguards in grounded trails;
  • semantic topic bridges between memory nodes.

Choose a trail in Preserved reasoning, then choose a memory card to inspect its role, source grounding, and named relationships. Open complete memory returns to the Memory Intelligence drawer.

No decision trails yet does not mean there are no links. It means the snapshot has no qualifying explicit memory-to-memory decision/evidence/guard component. Topic/entity links and semantic bridges can still exist.

Projects: define where managed memory belongs

Projects governs new project-scoped actions; it is not required merely to read the overall snapshot.

In the disclosed Example workspace, Projects explains this boundary and links back to Memory Intelligence or Recall; it does not simulate registration or claim that a project was changed. The controls below appear only when a verified local management session returns a real registry.

Registry state

State Meaning
Compatibility Existing unscoped behavior remains available while legacy memory is reviewed
Strict New memory requires one active registered project and cross-project delivery is disabled
Needs attention / Invalid The registry projection cannot be proven or validated; changes are disabled
Management enabled The short-lived local session can call named project controls
Read-only Registry information can be visible, but project controls are locked

If the projection reports isolated scope and sharing off, Home displays that fact explicitly. It never fabricates Compatibility when registry state is missing or invalid.

Registry summary

The four counters are:

  • Registered — total project mappings;
  • Active — mappings eligible for current sessions;
  • Revision — authoritative registry revision;
  • Unassigned — legacy memories with no declared project.

Registered projects

Each row shows display name, Active/Inactive state, canonical root, a shortened stable project ID, and Folder missing when the root is unavailable.

Control Effect
Add project Register an existing absolute, specific project folder
Edit Rename or move the registration while preserving its stable project ID
Activate / Deactivate Change whether the project can own a Home session; a missing folder cannot be activated
Remove Remove only Elefante's registry mapping after acknowledgement

Removing a registration does not delete the project folder or any memory. Deactivation can be rejected when strict mode would be left without another usable active project.

Legacy memory review

Fully unassigned older memories remain available under Compatibility until the user chooses where they belong. Elefante never guesses a project from memory text.

The review lists 25 records per page with Previous/Next controls. Choose project opens the explicit assignment dialog. A protected memory requires an additional acknowledgement; its protection is preserved and only the declared project is added. Success requires a VERIFIED_COMPLETE assignment receipt.

Enabling strict isolation

Enable strict is available only when:

  • the registry is currently in Compatibility mode;
  • at least one active project has an available folder;
  • the legacy scan completed;
  • zero fully unassigned memories remain;
  • local management is active.

The final acknowledgement is explicit. Strict mode is a one-way Home action and cannot be downgraded from this dashboard.

Recover: health, backup, restore, and support

Recover provides one trustworthy state, one safe next action, and verified protection before a data switch.

Without an operational receipt, Recover shows the evidence required for health, backup, restore, and support, but does not present those capabilities as ready. The snapshot can remain readable while lifecycle controls are unavailable.

Check health

Check health verifies runtime readiness, connected agent evidence, Recall, and backup evidence without reading memory content. It returns one of Ready, Needs attention, Recovery required, or Unsupported, individual named checks, verified/invalid backup counts, and one safe next action.

If the next action is Backup, Restore, or Support report, Home links directly to that flow. Product-code repair is handed to the official package rather than performed by the running app.

Back up now

The flow is deliberately two-stage:

  1. Inspect backup reports estimated file count, size, configured destination, and the steps Elefante will take. Home cannot redirect durable data to an arbitrary path.
  2. A checkbox acknowledges that writes pause briefly, then Create verified backup executes the one-use plan.

Completion requires archive readback, staged restoration, and database verification. A failed untrusted archive is removed rather than presented as a backup.

Restore a backup

  1. Find verified backups lists only archives in the configured backup location; invalid archives are counted and excluded.
  2. Choose one archive and Inspect selected backup.
  3. Supply a private Recall question that the restored state should answer. It is used once and is not written to the recovery receipt.
  4. Acknowledge the safety plan, then Restore with rollback protection.

Elefante creates a verified backup of current data before switching. It stages and checks the selected archive before activation, then verifies active files, Home, and scoped Recall. Any failed final check triggers restoration of the exact previous data. If rollback cannot be proven, the terminal state is UNSAFE.

Support report

Preview support report shows every category before creation. The result is one private local ZIP that is downloaded by the browser and never transmitted by Elefante.

The preview can include:

  • product and build identity;
  • operating system, architecture, and Python version;
  • customer readiness and verified agent-connection counts;
  • Recall and backup readiness facts;
  • bounded diagnostic codes;
  • content-free recovery and package receipts.

It never includes:

  • memory content;
  • project names or paths;
  • prompts, questions, answers, responses, or transcripts;
  • credentials or environment values;
  • host configuration contents;
  • logs.

After acknowledgement, Create and download report writes, reads back, and downloads the allowlisted ZIP. A failed report is removed. A verified receipt offers Download ZIP again.

Safety boundary

Recover owns product health, verified backup, verified data restore, and the privacy-safe support report. Two operations intentionally live elsewhere:

  • permanent memory deletion belongs to Correct's verified gate;
  • product code changes belong to the exact official package.

Product maintenance handoff

Home shows status for, but does not execute, four package operations. These are installer actions, not dashboard controls:

Operation Package authority
Repair Matching official package reinstalls owned code and connections while preserving data
Update Newer official package backs up, switches code, verifies Recall, and rolls code back on failure
Roll back code Current official package returns to one retained verified code version; it does not claim to undo memory changes
Uninstall Matching official package backs up and removes unchanged Elefante-owned code/connections while preserving memories

The customer journey is open the official package -> review and confirm -> return to Home and Check health. The last content-free package receipt appears only after the health check loads it.

Recovery receipts

Recover shows the operation, terminal state, bounded archive label, file count, size, safety-backup label when applicable, verification checks, and named next action. Recent receipts shows at most five bounded lifecycle entries.

Terminal state Meaning in Recover
VERIFIED_COMPLETE Backup, restore, or report and its readback checks completed
FAILED_NO_CHANGE The requested switch did not occur
FAILED_ROLLED_BACK Failure was contained and the prior state or untrusted output was safely restored/removed
NEEDS_HUMAN The inspected plan no longer matches current evidence
RUNNING The operation was interrupted or may still be running; inspect before starting another
UNSAFE Safe rollback could not be proven; do not retry automatically

Do not interpret an empty or stale snapshot as proof that the live store is empty. Regeneration is a separate explicit action.

Header-stat and Session Intelligence fetch failures currently log to the browser console without a dedicated visible error. Unexpected zero/unknown header values or an unexpected Off by default panel should therefore be verified against /api/stats or /api/session-intelligence before being treated as product truth.

Responsive and accessibility behavior

  • At phone width, product identity and status controls occupy separate header rows; the example/status label can shrink while theme and Reload snapshot remain visible.
  • The top tab bar scrolls horizontally on narrow screens.
  • The Memory Intelligence table hides secondary columns on narrow screens; the detail drawer becomes full-width.
  • Light is the default presentation for a new browser profile. The header theme control preserves an explicit dark choice in that browser.
  • Project dialogs trap keyboard focus and return it to the prior control.
  • Correction, Resolve, Remember, assignment, and project dialogs support Escape, subject to their in-progress safety locks.
  • Current limitation: Related-memory cards in the detail drawer are clickable non-button elements, so complete keyboard behavior is not guaranteed by the source contract.

Privacy and security boundary

The snapshot is pattern-redacted, not anonymized. It can still contain private memory content. Keep Home on loopback and do not expose port 8000 to a network without a separately authenticated operator boundary.

The default allowed browser origins are:

  • http://localhost:8000
  • http://127.0.0.1:8000

The snapshot server exposes read-only GET routes:

  • /api/graph
  • /api/search
  • /api/stats
  • /api/session-intelligence
  • /api/control-config, which exposes only the configured loopback daemon port

Named management requests go to the daemon's separate local control service and require its short-lived origin-bound capability. Home cannot regenerate the snapshot, open the stores, run arbitrary tools, or select arbitrary backup or support-report destinations.

Troubleshooting

I see an older or simpler dashboard

Confirm the installed build, not only the semantic version in the header. The six-workspace, light-default dashboard described here is currently a verified source prototype. This work did not replace the installed runtime or publish a package. If the dashboard does not show Home, Recall, Memory Intelligence, Connections, Projects, and Recover, the running package still owns earlier dashboard assets. This is a package-version boundary, not a second Elefante product.

Home has no operational receipt

Continue with Global understanding if the snapshot is available. If you expected live Recall or lifecycle controls, verify the installed Elefante service and use Recover's evidence model. Do not install a browser connector and do not treat a visible snapshot as proof that an operation ran.

Recall has no evidence yet

This means no Recall receipt was returned in the current environment. A real check requires one exact active project and one question. The page must not claim supplied, no match, blocked, or unavailable until that check returns.

Snapshot is empty or stale

Use elefante-DashboardOpen(refresh=true) from a connected agent to regenerate the snapshot, or use the source pipeline below. Header Reload snapshot alone cannot regenerate it.

Graph says No decision trails yet

Inspect Topics and Vitality first. The snapshot can contain many topic, entity, or semantic links without the explicit memory-to-memory edges required for a grounded decision trail.

The local dashboard address is unavailable

This is a transport diagnostic, not a product workflow. First test whether the existing process is the healthy Elefante dashboard. Do not kill an unknown process blindly.

curl --fail http://127.0.0.1:8000/health
curl --fail http://127.0.0.1:8000/api/stats

Expected dashboard health response:

{"status":"ok","service":"elefante-dashboard"}

This response proves the dashboard HTTP process, not the daemon, Recall, project, or backup. Use Home or Recover for the complete product state.

Browser reports a CORS or connection error

Use the exact loopback URL. External origins require an explicit ELEFANTE_DASHBOARD_CORS_ORIGINS list and a separately authenticated network boundary.

Snapshot export reports a Kuzu lock

Wait for the current transaction or stop the competing database-owning source process. Follow Kuzu troubleshooting. Never delete Kuzu's internal lock file as a default repair.

Source-checkout workflow

Installed customers do not need a source checkout. Developers can generate, validate, and serve a snapshot explicitly:

./.venv/bin/python scripts/pipeline/update_dashboard_data.py
./.venv/bin/python scripts/verify/verify_dashboard_snapshot.py \
  --path ~/.elefante/data/dashboard_snapshot.json
./.venv/bin/python -m src.dashboard.server

Then open http://127.0.0.1:8000.

The standalone pipeline opens configured stores while exporting. Do not run it beside another direct database-owning source process. For an installed daemon, prefer the governed elefante-DashboardOpen(refresh=true) path.

Safe showcase

To inspect the visual surface without opening or changing a real memory store:

./.venv/bin/python scripts/demo/generate_showcase_snapshot.py \
  --output /tmp/elefante-showcase/dashboard_snapshot.json
ELEFANTE_DATA_DIR=/tmp/elefante-showcase \
  ./.venv/bin/python -m src.dashboard.server

The maintained showcase is deterministic, source-grounded, and explicitly labelled Example workspace. It supports inspection and workflow explanation but never advertises live control or an operation receipt. Its counts are not customer usage or product-performance evidence.
